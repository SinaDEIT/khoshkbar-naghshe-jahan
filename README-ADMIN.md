# پنل مدیریت قیمت (مخصوص GitHub Pages)

- قیمت و لیبل‌ها در فایل `products.json` است. سایت آن را می‌خواند.
- صفحه‌ی `/admin.html` همان فایل را از طریق API گیت‌هاب ویرایش و commit می‌کند؛ گیت‌هاب پیجز خودش سایت را به‌روز می‌کند (۱ تا ۲ دقیقه).
- ورود = توکن گیت‌هاب شما. بدون توکن، صفحه فقط یک فرم خالی است.

## ساخت توکن (یک بار)
GitHub ← Settings ← Developer settings ← Personal access tokens ← **Fine-grained tokens** ← Generate:
- Repository access: **Only select repositories** ← همین ریپازیتوری
- Permissions ← Repository permissions ← **Contents: Read and write**
- مدت اعتبار: مثلاً ۹۰ روز

توکن را جای امنی نگه دارید و هیچ‌جا در ریپازیتوری ننویسید.

## دسته‌بندی‌ها (دکمه‌ی «دسته‌بندی‌ها» در بالای پنل)
- **افزودن دسته‌ی جدید:** «+ افزودن دسته‌بندی» ← نام را بنویسید ← یک آیکون آماده انتخاب کنید یا عکس/آیکون خودتان را آپلود کنید ← «ذخیره‌ی تغییرات».
- **عکس دسته:** هر عکسی (ترجیحاً PNG یا WebP با پس‌زمینه‌ی شفاف) آپلود کنید؛ پنل خودش آن را به ۱۲۸×۱۲۸ و حدود ۱۲ کیلوبایت کوچک می‌کند. برای دسته‌های آماده (پسته، عسل و …) هم می‌شود عکس گذاشت؛ جای آیکون فعلی را می‌گیرد. با «×» به آیکون اصلی برمی‌گردد.
- **حذف دسته:** فقط دسته‌های جدید حذف می‌شوند و فقط وقتی هیچ محصولی در آن‌ها نباشد.
- داده‌ها در فایل `categories.json` و عکس‌ها در `assets/img/categories/` ذخیره می‌شوند. دسته‌ی جدید خودکار در منو، فیلتر فروشگاه و صفحه‌ی اصلی دیده می‌شود و آدرسش `shop.html?category=...` است.
- دسته‌های آماده (از جمله «عسل») صفحه‌ی ثابت جداگانه برای سئو دارند. دسته‌های جدید این صفحه‌ی ثابت را ندارند.

# قابلیت‌های جدید (v29)

همه‌ی این قابلیت‌ها بدون سرور کار می‌کنند و فایل‌های داده‌شان فقط وقتی لازم شوند بارگیری می‌شوند.

## ارتباط سریع (دکمه‌ی گرد گوشه‌ی صفحه)
شماره و لینک را از **فوتر** می‌خواند؛ پس فقط همان‌جا را ویرایش کنید (در `index.html`، `shop.html` و بقیه‌ی صفحه‌ها، سپس `python3 tools/build-category-pages.py`):
- تلفن: لینک `tel:` در بخش «تماس با ما» (فعلاً شماره‌ی نمونه است).
- تلگرام: آیکن تلگرام در فوتر را به `https://t.me/آیدی-شما` تغییر دهید. تا وقتی `#` باشد، گزینه‌ی تلگرام نمایش داده نمی‌شود.

## گالری، توضیحات و مشخصات محصول (در «مشاهده سریع»)
فایل `product-info.json` (جدا از `products.json` تا پنل ادمین آن را پاک نکند). عکس‌های بیشتر را در `assets/img/products/` بگذارید (WebP، حدود ۴۰ تا ۸۰ کیلوبایت، با نام‌های متفاوت از عکس اصلی) و ثبت کنید:
```json
{
  "p6": {
    "imgs": ["nokhodchi-do-bu-2.webp", "nokhodchi-do-bu-3.webp"],
    "desc": "توضیح واقعی محصول",
    "specs": [["بسته‌بندی", "زیپ‌کیپ"], ["مبدأ", "..."]]
  }
}
```
عکس اصلی همان فیلد `i` در پنل ادمین است و اولین تصویر گالری می‌شود. با کمتر از دو عکس، نمای قبلی بدون تغییر می‌ماند. ردیف‌های دسته، وزن‌های موجود و قیمت هر کیلو همیشه از داده‌ی واقعی ساخته می‌شوند.

## نظر خریداران
- نظرهای عمومی در `reviews.json` هستند (فعلاً خالی). **فقط نظر واقعی و با رضایت مشتری** اضافه کنید: `{"n":"نام","r":5,"t":"متن نظر","d":"۱۴۰۵/۰۸/۱۰","p":"نام محصول (اختیاری)"}`
- نظری که بازدیدکننده می‌نویسد فقط در مرورگر خودش ذخیره می‌شود و به شما نمی‌رسد. دکمه‌ی «ارسال برای فروشگاه» متن را کپی و تلگرام فروشگاه را باز می‌کند؛ پس از بررسی، خودتان به `reviews.json` اضافه کنید.

## ضمانت و باشگاه مشتریان
- متن بخش «ضمانت» در `index.html` است و باید با «سوالات متداول» هم‌خوان بماند. مهلت اعلام مشکل (TODO داخل فایل) پس از تأیید شما اضافه شود.
- «پیشنهاد ویژه‌ی روز» از محصولاتِ دارای قیمت قدیمی (`old`) در `products.json` انتخاب می‌شود. نشان‌ها فقط یادگاری‌اند و در مرورگر کاربر ذخیره می‌شوند؛ تخفیف یا امتیازی به آن‌ها وابسته نیست.
